# Символьный поиск

Этот эксперимент не участвует в формировании приложенного `answer.csv`.
Отправляемая версия использует 38 признаков, PairLogit с 80 деревьями
и объединение выдач, описанное в [основном README](../README.md).

`char_retrieval.py` проверяет дополнительный поиск по заголовкам.
TF-IDF векторизует фрагменты длины 3-5 символов внутри слов (`char_wb`).
Например, «шумоизаляция» и «шумоизоляция» сохраняют много общих фрагментов.
Стемминг в этом канале не применяется; текст приводится к нижнему регистру,
`ё` заменяется на `е`, лишние пробелы убираются.

На dev покрытие пула выросло с 93,03% до 93,46%: найдены 9 ранее пропущенных
объявлений. Замер: [char_retrieval.json](../results/experiments/char_retrieval.json).
Время полного эксперимента на CPU - около 98 секунд.

Для каждого dev-запроса добавляются до 300 объявлений с наибольшим косинусным
сходством. Скрипт сравнивает покрытие положительных пар исходным и расширенным
пулами на всех 2 000 запросах при стандартных настройках. Для каждого запроса
считается доля найденных положительных объявлений, затем берётся среднее.
Метки используются только для оценки.

После выполнения `notebooks/solution.ipynb` с `rebuild = True` выполнить команды
из корня репозитория. Здесь `python` должен указывать на интерпретатор
окружения проекта.

```bash
python -m pip install -r requirements/experiments.txt
python experiments/char_retrieval.py --validation work/validation --features work/quality/dev_expanded.parquet --output work/char_retrieval.json
```

Пути `--validation` и `--features` должны указывать на созданные локальные файлы.
При стандартном `configs/improved.toml` это `work/validation/` и
`work/quality/dev_expanded.parquet`. Файл признаков уже содержит кандидатов
текущего решения, включая поиск в радиусе 50 км. Его запросы и `doc_id` должны
соответствовать тому же каталогу validation. При изменении `work_dir` нужно
заменить пути в команде. Быстрая проверка `check.ipynb` эти dev-признаки
не создаёт. В поставляемом репозитории промежуточных данных нет.

Это отдельный эксперимент с поиском кандидатов. Он не меняет модель и
`answer.csv`. Покрытие пула нельзя считать итоговым Recall@50: новые кандидаты
ещё должны пройти ранжирование. Для включения в решение нужно пересчитать
обучающие признаки, переобучить модель и проверить итоговую метрику.
