# Candidate generation для поиска услуг Авито

Решение выбирает 50 объявлений для каждого запроса: BM25 и похожие запросы из train
находят кандидатов, CatBoostRanker формирует итоговую выдачу.
Готовый ответ для 2 452 запросов находится в `answer.csv`.
GPU и внешние API не нужны.

## С чего начать проверку

| Задача | Что открыть | Что получится |
| --- | --- | --- |
| Получить ответ заново и сравнить с приложенным | [check.ipynb](notebooks/check.ipynb), инструкция ниже | Новый поиск, признаки и предсказания с готовой моделью; проверка точного совпадения CSV |
| Разобраться в решении до запуска | [Карта пайплайна](docs/pipeline.md) и [описание метода](docs/approach.md) | Порядок этапов, их входы и результаты, причины выбора признаков и алгоритмов |
| Просмотреть сохранённые метрики | [solution.ipynb](notebooks/solution.ipynb), `rebuild = False` | Результаты подбора и оценки без повторного обучения; исходные Parquet для этого режима не нужны |
| Повторить обучение и оценку | [solution.ipynb](notebooks/solution.ipynb), `rebuild = True` | Обучение итоговой модели, выбор по dev, оценка на holdout и генерация CSV |

Для всех режимов нужно установить окружение по инструкции ниже.
В ноутбуках уже задан порядок выполнения; запускать модули вручную не требуется.

## Состав репозитория

```text
notebooks/
  check.ipynb             пересчёт benchmark с готовой моделью
  solution.ipynb          подготовка, обучение, оценка и итоговый CSV
src/
  avito_retrieval/        обработка текста, BM25, метрика и проверка CSV
  avito_ranker/           исходный поиск, признаки и модель для сравнения
  avito_improved/         история запросов, география, обучение и выбор выдачи
configs/                 пути к данным и параметры запуска
requirements/            зафиксированные версии библиотек
results/
  improved/              текущая модель, метрики и проверки
  ranker.cbm             фиксированная исходная модель
  README.md              назначение моделей и сохранённых результатов
tests/                   27 автоматических тестов
experiments/             отдельная проверка символьного поиска
docs/                    описание метода и выполненных проверок
data/                    сюда нужно положить исходные Parquet
answer.csv               файл для отправки
```

Оба ноутбука вызывают этапы через `src/avito_improved/run.py`.
`history.py` строит историю запросов; `retrieval.py` и `geo.py` ищут кандидатов;
`dataset.py` считает признаки; `model.py` обучает модель; `selection.py` выбирает
выдачу; `evaluation.py` считает Recall и сохраняет CSV.
`protocol.py`, `audit.py` и `artifacts.py` отвечают за разбиение, проверки и загрузку модели.
Промежуточные файлы создаются в `work/` и в репозиторий не входят.

Подробная навигация: [модули и основные функции](src/README.md),
[модели и отчёты](results/README.md), [настройки](configs/README.md),
[проверки кода](tests/README.md), [окружение и зависимости](requirements/README.md).

## Данные и признаки

Используются только три файла задания. `train.parquet` содержит 497 673 пары
«запрос - выбранное объявление»: по ним строятся разметка и история запросов.
`benchmark_queries.parquet` содержит 2 452 запроса для ответа,
`benchmark_items.parquet` - 189 212 объявлений, среди которых нужно искать.

| Что используется | Зачем |
| --- | --- |
| Текст запроса, заголовок, описание и параметры объявления | Найти совпадения по услуге; учесть слова, которых нет в заголовке |
| Поисковые фильтры и параметры объявления | Учесть уточнения запроса, например вид услуги |
| Локация, координаты, категория и флаг доставки | Учесть место поиска и контекст запроса |
| Положительные пары из обучающих групп | Найти объявления и подкатегории, которые выбирали по похожим запросам |
| Цена, рейтинг, число отзывов и доступность связи | Дать модели дополнительные различия между текстово похожими объявлениями |

Из этих данных получаются 38 численных признаков: оценки и позиции BM25,
совпадения слов, сходство с историей, расстояние и свойства объявления.
`query_id` и `item_id` нужны для сопоставления строк и сохранения ответа,
но не подаются в модель как признаки.
Подробнее: [данные, признаки и обучение](docs/approach.md).

## Как устроено решение

1. **Разбиение.** Нормализуем тексты и применяем русский Snowball-стеммер.
   Запросы с одинаковым набором полученных токенов попадают в одну группу.
   Каждая группа целиком относится к train, dev или holdout.
   Для итоговой оценки заранее отложены 1 000 ранее не использовавшихся запросов.
2. **Кандидаты.** BM25 ищет по заголовку, описанию и параметрам во всём корпусе
   и в локации запроса. Дополнительные кандидаты находятся по фильтрам,
   похожим обучающим запросам и в радиусе 50 км от центра локации.
   История использует только train; при подготовке обучающего примера из неё
   исключается вся группа этого запроса.
3. **Модель.** CatBoostRanker использует 38 признаков: текстовые совпадения,
   оценки BM25, подкатегории из истории, расстояние, фильтры и свойства объявления.
   Сравниваются PairLogit и QuerySoftMax. По dev выбран PairLogit с 80 деревьями.
   Исходная модель из `results/ranker.cbm` помогает выбирать сложные отрицательные примеры.
4. **Топ-50.** Берём 40 объявлений новой модели и дополняем выдачей исходной,
   пропуская повторы. Способ поиска и доля каждой выдачи выбраны по dev.
   Перед оценкой на новом holdout фиксируются модель, код и история.
5. **Ответ.** Для benchmark поиск выполняется только среди его 189 212 объявлений.
   Проверяются все query_id, принадлежность item_id корпусу, уникальность и формат CSV.

В репозитории нужны обе модели. `results/improved/ranker.cbm` ранжирует кандидатов
по 38 признакам. `results/ranker.cbm` использует исходные 31 признак, участвует
в выборе отрицательных примеров и дополнении итогового топ-50.
Полный запуск обучает итоговую модель заново, а исходную берёт из репозитория
как фиксированную часть решения.

В ноутбуках используются вызовы вида `run_stage("benchmark_features", config_path)`.
Первый аргумент - этап расчёта, второй - настройки. Ячейки задают порядок работы,
а реализация вынесена в небольшие модули, общие для обоих ноутбуков.
Каждый этап запускается отдельным процессом, чтобы освобождать память после работы.
Подробный вывод записывается в `results/improved/logs/`; в ячейке виден его конец.
В [карте пайплайна](docs/pipeline.md) для каждого этапа указаны входы, выходы и код.

## Результаты

| Метод | Dev, 2 000 запросов | Новый holdout, 1 000 запросов |
| --- | ---: | ---: |
| BM25 + RRF | 28,96% | 27,88% |
| Исходный BM25 + CatBoost | 74,10% | 73,58% |
| История запросов + география + CatBoost | **78,32%** | **78,48%** |

Все методы в таблице проверены на одинаковом локальном корпусе из 515 895 объявлений.
Recall@50 усредняется по запросам; пропущенные при поиске положительные объявления
остаются в знаменателе. Отчёт: [fresh_metrics.json](results/improved/fresh_metrics.json).
Исходный вариант получил на платформе Авито **0,770104**.
Отчёты первой версии сохранены в `results/`, текущей - в `results/improved/`.

## Проверка качества и ошибок

**Оценка качества**

1. **Подбор на dev.** На 2 000 запросов сравнивались модели, способы поиска
   кандидатов и объединения выдач. По Recall@50 выбран итоговый вариант.
2. **Проверка на holdout.** После фиксации кода и параметров решение оценено
   на отдельных 1 000 запросов. Recall@50 составил **78,48%**.
3. **Проверка разделения данных.** История запросов строится только по train.
   Группы dev и holdout в неё не входят. Для обучающего запроса исключается
   и его собственная группа, чтобы история не подсказывала известный ответ.
   Отчёт: [leakage_audit.json](results/improved/leakage_audit.json).

**Ошибки и изменения в решении**

- **Нужное объявление не найдено среди кандидатов.** Добавлены поиск по фильтрам,
  история похожих запросов и поиск в радиусе 50 км. Это расширяет список,
  из которого модель выбирает ответ. На holdout среднее покрытие положительных
  объявлений кандидатами составляет **93,50%**.
- **Объявление найдено, но не вошло в топ-50.** Добавлены признаки истории
  и расстояния, обучение на сложных отрицательных примерах и объединение
  двух выдач. Эти варианты сравнивались по итоговому Recall@50 на dev.

Примеры запросов и причины оставшихся пропусков приведены в
[анализе ошибок](docs/error_analysis.md). Отдельные эксперименты с символьным
TF-IDF и связями локаций сохранены для дальнейшей работы; в текущий ответ они не входят.

**Проверка кода и ответа**

- Прошли **27 автоматических тестов**. Проверены состав query_id, принадлежность
  item_id корпусу, отсутствие повторов и ограничение в 50 объявлений.
- Полный пересчёт benchmark с готовой моделью проверен в новом окружении.
  Текущий CSV также проверен повторным предсказанием по сохранённым признакам.
  Повторное обучение в чистом окружении не выполнялось.
- Для проверки результата запустите `notebooks/check.ipynb` по инструкции ниже.
  Ноутбук пересчитает поиск, признаки и предсказания и сравнит полученный файл
  с `answer.csv` побайтово. Отчёты и условия проверки описаны в
  [документации по воспроизводимости](docs/reproduction.md).

## 1. Быстрая проверка решения

Пересчитывает поиск и признаки для всех запросов benchmark, применяет готовую модель
и сравнивает новый CSV с приложенным побайтово. Также запускает 27 тестов.

**1.** Установить Python 3.12.10, скачать репозиторий и положить в `data/`:

```text
train.parquet
benchmark_queries.parquet
benchmark_items.parquet
```

Файлы нужно распаковать непосредственно в `data/`, без дополнительной вложенной папки.
Источник данных и настройка другого пути описаны в [data/README.md](data/README.md).

**2.** Открыть терминал в корне репозитория и выполнить команды своей ОС.

**Windows / PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements/notebook.txt
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name avito-ranking --display-name "Avito ranking"
.\.venv\Scripts\python.exe -m jupyterlab notebooks/check.ipynb
```

**Linux / macOS:**

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements/notebook.txt
.venv/bin/python -m ipykernel install --sys-prefix --name avito-ranking --display-name "Avito ranking"
.venv/bin/python -m jupyterlab notebooks/check.ipynb
```

**3.** Выбрать ядро **Avito ranking** и нажать **Run → Run All Cells**.
Проверка последовательно выполнит тесты, восстановит историю, проверит сохранённую
модель, построит индексы benchmark, пересчитает признаки и сформирует CSV.
Последняя ячейка должна показать `status: passed`, `answer_identical: true`,
`rows: 2452`, `min_items: 50` и `max_items: 50`.
Новый файл появится в `work/quality/answer.csv`, отчёт - в `work/quality/check_report.json`.
Корневой `answer.csv` служит эталоном для сравнения и этим ноутбуком не перезаписывается.

Ориентир для проверки: **8,4 минуты**, без установки зависимостей.
Обучение здесь не повторяется. `train.parquet` нужен для восстановления истории
запросов и центров локаций. Установку окружения достаточно выполнить один раз.

Если нужно проверить только код без расчёта benchmark, команды для запуска
27 тестов приведены в [tests/README.md](tests/README.md).

## 2. Полный запуск решения

1. Подготовить окружение и три файла данных по инструкции выше.
2. Открыть `notebooks/solution.ipynb` и выбрать ядро **Avito ranking**.
3. В первой кодовой ячейке поставить `rebuild = True`.
4. Нажать **Run → Run All Cells**. Итоговый `answer.csv` появится в корне репозитория.

Ноутбук строит индексы, готовит обучающие пары, сравнивает две функции потерь,
выбирает модель по dev, проверяет её на holdout и формирует ответ.
При `rebuild = False` он показывает сохранённые результаты сразу, без обучения.
Пути меняются в `configs/improved.toml`; отчёты полного запуска перезаписываются.

Результаты каждого шага остаются в `work/`. После завершения `export` выбранная
модель, параметры и отчёты записываются в `results/improved/`, а рассчитанный
ответ копируется в корень. Назначение файлов описано в [results/README.md](results/README.md).
Для отдельного повторного обучения удобно использовать новую копию репозитория,
чтобы рядом оставались исходные артефакты для сравнения.

Полный цикл существенно дольше быстрой проверки: только обучение двух моделей
в проведённом эксперименте заняло около 34 минут. Индексы и признаки считаются отдельно.
Вычисления проверялись на Windows, CPU, 8 ГБ RAM; используются два потока.
Linux и macOS отдельно не проверялись. Подробности: [docs/reproduction.md](docs/reproduction.md).

### Если запуск остановился

- **Не найден Parquet.** Проверьте три имени файлов и `data_dir` в `configs/improved.toml`.
  Относительные пути в настройках считаются от папки `configs/`.
- **Не находится модуль или ядро.** Установите `requirements/notebook.txt` из корня
  репозитория и выберите ядро **Avito ranking**, созданное тем же Python из `.venv`.
- **Этап завершился с ошибкой.** Откройте указанный в сообщении файл из
  `results/improved/logs/`. В нём сохраняется полный вывод, даже если в ячейке он сокращён.
- **Не совпали контрольные суммы или CSV.** Сверьте данные, код и модели с одной
  версией репозитория. Проверка намеренно останавливается при расхождении;
  не нужно отключать её или вручную менять контрольные суммы.
