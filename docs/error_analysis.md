# Разбор ошибок

Разбор выполнен на dev из 2 000 запросов по известным положительным парам.
Скрытая разметка benchmark не использовалась. Место объявления ниже указано
в выдаче новой модели до объединения с исходной.
Это версия с 38 признаками и 80 деревьями, которая формирует приложенный `answer.csv`.
Символьный поиск и обучаемые связи локаций ниже приведены как отдельные
эксперименты и варианты улучшения; в приложенном ответе они не используются.

Все известные положительные объявления найдены для 1 554 запросов.
У 145 запросов хотя бы одно объявление отсутствует среди кандидатов,
у 306 найденный кандидат не вошёл в итоговый топ-50. Пять запросов входят
в обе группы. Другие объявления из выдачи не считаются заведомо нерелевантными:
отсутствие положительной пары этого не доказывает.

## Примеры

### 1. Опечатка в ключевом слове

Запрос: **«шумоизаляция потолка»**.
Выбранное объявление: **«Шумоизоляция стен,потолков,пола»**,
`b0d25f429bd18bd1`. Не попало в кандидаты.

**Наблюдение.** В описании есть «Шумоизоляция потолков», в параметрах
«Название услуги Шумоизоляция потолка». В запросе ошибка в слове «шумоизаляция».
Кроме того, для его локации отсутствует рассчитанный центр.

**Гипотеза.** Поиск по токенам теряет главное слово, а географический канал
не компенсирует потерю. В отдельном эксперименте символьный поиск нашёл
объявление на 221-м месте и вернул его в пул кандидатов.

### 2. Для локации запроса нет центра

Запрос: **«подключить водонагреватель»**.
Выбранное объявление: **«Ремонт, Установка Бойлеров Водонагревателей Котлов»**,
`d1148ec5bc5d929f`. Не попало в кандидаты.

**Наблюдение.** В описании прямо указано «Подключение накопительных и проточных
водонагревателей». Локация запроса `622470`, объявления `622500`.
Для локации запроса отсутствует рассчитанный центр, поэтому поиск в радиусе
50 км не даёт дополнительных кандидатов.

**Гипотеза.** Глобальной текстовой выдачи недостаточно, а локальные каналы здесь
не помогают. Можно учить связи между локацией поиска и локациями выбранных
объявлений на train и использовать их как мягкую географическую оценку.

### 3. Одна услуга описана разными словами

Запрос: **«подруга на час»**.
Выбранное объявление: **«Выслушаю ваши проблемы»**,
`fb320bf56fbddca6`. Не попало в кандидаты.

**Наблюдение.** Описание: «Выслушаю и поддержу вас в нужный вам момент времени».
Общих слов с запросом почти нет.

**Гипотеза.** В этом случае нужен поиск по смыслу или расширение запроса
по обучающим парам. Символьное сходство само по себе не свяжет эти формулировки.
Близкий смысл не доказывает, что все условия услуги совпадают.

### 4. Услуга есть в описании, но заголовок общий

Запрос: **«повесить карниз для штор потолочный»**.
Выбранное объявление: **«Услуги мастер на час, муж на час»**,
`e187065250c42c06`. Найдено, но заняло **91-е место**.

**Наблюдение.** В описании есть «Повесить карниз», в параметрах «Услуга Установка
карнизов». Локация совпадает, слов запроса в заголовке нет.

**Гипотеза.** Модель недостаточно оценивает нужный пункт в длинном перечне работ.
Можно разбить описание и прайс на короткие фрагменты и добавить сходство
с лучшим фрагментом как признак.

### 5. Кандидат потерян при объединении выдач

Запрос: **«ведущий вокал»**.
Выбранное объявление: **«Ведущий, тамада»**,
`8eda547ca45fbdf5`. Заняло **41-е место** новой модели.

**Наблюдение.** В описании есть «Проведение свадеб, юбилеев, корпоративов»,
в параметрах «Своя музыкальная аппаратура». Текущая схема берёт только первые
40 новых кандидатов; через исходную выдачу это объявление не вернулось.
Наличие вокала в тексте не подтверждено.

**Вывод.** Здесь известен конкретный этап потери. Стоит проверить общее
ранжирование объединённых выдач. Просто увеличить долю новой модели недостаточно:
схема 40 + дополнение выбрана по общей метрике dev и выигрывает на других запросах.

### 6. Пара не объясняется доступным текстом

Запрос: **«ремонт стиральных машин на дому»**.
Выбранное объявление: **«Страхование авто»**,
`c0d4e4d7121c358f`. Не попало в кандидаты.

**Наблюдение.** Описание также состоит из «Страхование авто», в параметрах есть
«Услуга Страхование грузов». Ремонт стиральных машин в доступных полях не указан.

**Гипотеза.** Возможны шум в положительных парах или изменение объявления.
По этим данным нельзя подтвердить причину. Пара остаётся в оценке:
вручную удалять её или добавлять объявление в ответ нельзя.

## Отдельная проверка географии

У 347 из 2 000 dev-запросов `search_location_id` отсутствует в таблице центров
`history/location_centers.parquet`. Среди них 197 запросов имеют неполный ответ.
У остальных 1 653 запросов таких случаев 249.

| Локация запроса | Полностью найдены все положительные объявления | Доля полных попаданий |
| --- | ---: | ---: |
| Центр не рассчитан | 150 из 347 | 43,2% |
| Центр рассчитан | 1 404 из 1 653 | 84,9% |

Это **доля запросов с полным попаданием, не Recall@50**. Связь заметная,
но таблица не доказывает, что все различия вызваны географией.

Отдельно посчитан Recall@50: **43,66%** для запросов без центра и **85,60%**
для остальных. У 346 из 347 запросов без центра есть обучающая история связей
между локацией поиска и локациями объявлений.

В истории нужная локация для запроса про водонагреватель занимает первое место
(58 из 75 голосов), для вывоза мусора в Новой Москве - второе (3 из 15),
для шумоизоляции - седьмое (156 из 6 725). Один голос соответствует уникальной
тройке `(strict_group, search_location_id, item_location_id)` из train.
Это проверка наличия полезного сигнала, а не замер качества нового алгоритма.
Числа сохранены в [location_probe.json](../results/experiments/location_probe.json).

Следующий вариант для проверки: оценить распределение
`search_location_id -> item_location_id` только по обучающим парам.
Для обучающих признаков нужна оценка вне своей группы запросов: исключение
группы или out-of-fold расчёт. Dev и holdout в подсчёт не входят.
Вероятность локации можно использовать как признак и для дополнительных
кандидатов, сохраняя общий поиск. Жёстко отбрасывать другие локации не следует.

## Проверка символьного поиска

TF-IDF по символьным n-граммам длины 3-5 проверен на заголовках всех
515 895 объявлений. Для каждого dev-запроса к исходному пулу добавлены
до 300 объявлений по косинусному сходству. Обучение TF-IDF использует только
тексты корпуса; положительные пары нужны для оценки.

| Пул кандидатов | Среднее покрытие положительных объявлений |
| --- | ---: |
| Исходный | 93,03% |
| С добавлением символьного поиска | 93,46% |

Вернулись 9 пропущенных объявлений для 9 запросов, в том числе
«шумоизаляция потолка», «такарные услуги», «шугаринк».
Полная проверка заняла около 98 секунд на CPU.
Это покрытие расширенного пула, **не итоговый Recall@50**.
Код и запуск: [experiments](../experiments/README.md).
Результат: [char_retrieval.json](../results/experiments/char_retrieval.json).

Следующий шаг - добавить символьное сходство в признаки, пересобрать
обучающие кандидаты и переобучить ранжирование. Отдельно проверить
связи локаций и поиск по фрагментам описаний.

Это предложения и отдельные эксперименты, а не описание уже включённых
изменений в `answer.csv`. Решение о включении принимается по метрике на всём dev,
после проверки воспроизводимости. Подбор по отдельным приведённым примерам
не заменяет такую оценку.
