# Метод и устройство кода

## Что делает решение

1. BM25 со Snowball ищет по заголовку, описанию и параметрам объявления. По каждому полю берём до 300 кандидатов из всего корпуса и до 150 из локации запроса. В локальной ветке остаются только текстовые совпадения. Глобальная ветка сохраняет возможность найти услугу из другой локации.
2. CatBoostRanker учится выбирать между кандидатами. Признаки: оценки и ранги BM25, исходный RRF, совпадение локации/категории, доставка, совпадения слов и фильтров, длины текстов, цена, рейтинг, число отзывов и доступность способов связи. `query_id`, `item_id` и номера строк в признаки не входят.
3. Для обучения берём найденные положительные пары и до 120 неотмеченных кандидатов на запрос. Половину последних выбираем из верхней части выдачи, половину — случайно. Неотмеченные кандидаты не являются доказанно нерелевантными: это ограничение поведенческой разметки.
4. Используем PairLogit, до 700 деревьев глубины 6, шаг 0.06. На dev сравниваем 10, 20, 30, 50, 80, 100, 150, 200, 300, 400, 500, 600 и 700 деревьев. Более короткие модели добавлены после того, как лучшей точкой исходной сетки оказались 100 деревьев; holdout в этот момент ещё не оценивался. Для проверки пользы обучения также сравниваем простой RRF с бонусом за локацию; его вес выбирается на dev из трёх заранее заданных значений.
5. Метод с лучшим dev Recall@50 формирует итоговые 50 объявлений. Равные оценки разрешаются по исходному `item_id`. При отсутствии текстовых совпадений пул содержит детерминированные 50 ID; это техническое заполнение, а не оценка релевантности.

Предобученных языковых моделей, ручных ответов под запросы и обращений к API здесь нет.

## Как отделено обучение от оценки

- Группа запроса — отсортированный набор Snowball-токенов после нормализации регистра, `ё`, пробелов и пунктуации. Перестановка слов и многие формы русских слов остаются в одной группе. Это не гарантирует объединение всех синонимов.
- Группа целиком попадает в train, dev или holdout. Выбирается один контекст на группу: 8 000 обучающих, 2 000 dev и 2 000 holdout-запросов. Контекст содержит все пять полей `search_*`.
- Все группы, просмотренные в прежней оценке baseline, доступны только для dev. Новый holdout с ними не пересекается. Правило выбора не использует попадания объявлений в выдачу.
- Корпус — все 515 895 уникальных объявлений из train и benchmark. Он выбирается независимо от положительных меток. При совпадении ID берём признаки из benchmark. Тексты объявлений для retrieval доступны в индексе, но разметка проверочных запросов не участвует ни в обучении, ни в признаках.
- Перед открытием holdout сохраняются SHA-256 модели, настроек и кода. Изменения после фиксации блокируют повторную оценку. Число деревьев и остальные решения выбираются до неё.
- В Recall учитываются все известные положительные объявления, включая не попавшие в пул. Сначала считаем долю для каждого запроса, затем обычное среднее. Повторные пары не увеличивают вес. Метрика дополнительно пересчитывается по строковым ID.

Здесь корпус больше, чем в первой версии и в benchmark. Числа разных протоколов нельзя напрямую сравнивать. В отчёте baseline и новая модель оцениваются на одних запросах и одном корпусе. Это локальный эксперимент по наблюдаемым положительным парам, не оценка скрытой разметки Авито. Без временных меток также нельзя проверить временное разделение.

После просмотра этого holdout он перестаёт быть новым тестом для дальнейшего подбора. Для новых экспериментов понадобится отдельная оценка. Финальная модель сохраняет обучение только на train: мы не переобучаем её на holdout после измерения качества.

## Файлы

- `results/answer.csv` — файл для загрузки в Авито.
- `results/dev_metrics.json`, `holdout_metrics.json` — качество на одинаковом протоколе и парный bootstrap прироста.
- `results/split_audit.json` — правила и проверки разбиения.
- `results/leakage_audit.json` — независимая проверка всех обучающих меток и исключения ID из признаков.
- `results/selected.json` — выбор только по dev.
- `results/ranker.cbm` — модель для локального повторения inference.
- `results/frozen_experiment.json` - контрольные суммы зафиксированного эксперимента с учётом переноса файлов. Исходные снимки и описание изменений сохранены рядом; подробнее в [проверке воспроизведения](reproduction.md).
- `results/verification.json` — независимая проверка метрики и CSV.
- `results/clean_environment.json` — повтор генерации кандидатов и предсказаний в чистом окружении с готовыми индексами и моделью; это не повтор обучения с нуля.
- `results/logs` — вывод каждого этапа.

`src/avito_ranker` содержит логику ранжирования; небольшие общие модули `src/avito_retrieval` - функции текстового поиска и проверки ответа. Ноутбуки находятся в `notebooks/` и вызывают эти модули. Исходные данные, окружение и индексы в архив не включаются.

## Обозначения в коде

| Имя | Что означает |
| --- | --- |
| `context_id` | Внутренний ID запроса вместе с его фильтрами |
| `strict_group` | Группа близких формулировок для разбиения |
| `qrels`, `positives` | Известные положительные пары |
| `doc_id` | Номер объявления внутри отсортированного корпуса |
| `pool` | Объединённый набор кандидатов до отбора 50 |
| `channels` | Кандидаты каждого поля и локальной ветки |
| `rrf` | Сумма обратных рангов трёх глобальных каналов |
| `matrix`, `names` | Матрица признаков и названия её столбцов |
| `label` | Найден ли кандидат среди известных положительных пар |
| `fold` | Часть данных: train, dev или holdout |
| `seed` | Начальное состояние для выбора отрицательных примеров и обучения модели; разбиение групп фиксировано отдельно |

## Использованные инструменты

- [BM25S](https://github.com/xhluca/bm25s) — реализация BM25; нормализация и параметры сохранены из baseline.
- [Snowball](https://snowballstem.org/algorithms/russian/stemmer.html) — русский стемминг.
- [RRF, SIGIR 2009](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) — объединение поисковых каналов.
- [CatBoostRanker](https://catboost.ai/docs/en/concepts/python-reference_catboostranker) и [PairLogit](https://catboost.ai/docs/en/concepts/loss-functions-ranking) — обучение отбора кандидатов.
- NumPy, SciPy, Polars и Apache Arrow — вычисления и таблицы; Jupyter — последовательный запуск.
